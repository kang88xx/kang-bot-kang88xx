## 체크인 사용법

브리핑을 받은 날 밤, 봇 채팅에 이렇게 답장합니다 (순서·형식은 자유, 줄바꿈이나 `/`로 구분):

```
운동: O (달리기 30분)
업무: 제안서 초안 / 미팅 2건
언어공부: X
```

다음 날 아침 브리핑 맨 위에 `운동 O · 업무 O · 언어공부 X`와 연속일수, 한두 문장 코멘트가 붙습니다.
기록은 `state/telegram_state.json`에 날짜별로 쌓이고 매일 커밋됩니다.

- 새벽 4시 전에 보낸 답장은 전날 체크인으로 칩니다 (자정 넘겨 써도 됩니다).
- 같은 날 여러 번 보내면 항목별로 합쳐지고, 메시지를 수정해도 반영됩니다.
- 항목은 줄 처음이나 `/`, `,` 뒤에서 `운동`·`업무`·`언어`(또는 `공부`)로 시작해야 인식됩니다. 메모 안에 들어간 단어는 무시합니다.

## 설정 바꾸기 (`config.yaml`)

| 항목 | 설명 |
|---|---|
| `sections[].feeds` | 섹션별 RSS 피드. 추가/삭제 가능 |
| `keywords` | 관심 키워드 목록. 키워드마다 구글뉴스 검색 섹션이 추가됨 (예: `- 반도체`) |
| `per_section` | 섹션당 기사 수 (기본 3). 텔레그램 길이와 비용에 영향 |
| `model`, `effort` | 요약 모델과 노력도. `claude-haiku-5-5`로 바꾸면 비용이 1/40 수준 |
| `source_names` | 기사 도메인 → 표시할 매체명 (예: `yna.co.kr: 연합뉴스`). 새 피드를 추가할 때 함께 지정, 없으면 피드가 알려주는 이름을 정리해 사용 |
| `max_candidates` | Claude에게 넘기는 섹션당 후보 수. 줄이면 비용 감소 |

발송 시각은 `.github/workflows/morning.yml`의 `cron` (UTC 기준, 한국시간 −9시간)을 고치면 됩니다.
예: 오전 7시 → `"0 22 * * *"`, 오전 8시 → `"0 23 * * *"`.

## 로컬에서 테스트

```bash
python main.py --skip-claude --dry-run   # 수집 + 페이지 생성 + 메시지 미리보기 (API 키 불필요)
python main.py --dry-run                 # Claude 요약까지 (텔레그램 발송은 생략)
python main.py                           # 실제 발송
```

`--dry-run`은 `state/telegram_state.json`을 건드리지 않습니다. 실제 발송은 같은 날 다시 실행해도
이미 보낸 메시지는 건너뛰므로(상태 파일에 기록) Actions 탭에서 재실행해도 중복 발송되지 않습니다.

## 동작 원리

```
체크인 답장 수집(checkin.py, getUpdates) → RSS 수집(news_fetch.py) → Claude 선별·요약+코멘트(summarize.py)
→ 구글뉴스 링크를 원문 주소로 변환(news_fetch.py) → docs/index.html 생성(page.py) → 텔레그램 발송(telegram.py) → 체크인 기록·페이지 커밋(워크플로)
```

- 구글뉴스 링크 → 원문 주소 변환은 최선 노력 방식입니다. 실패하면(연속 3회 실패 시 중단) 구글뉴스 주소를 그대로 사용합니다.
- 텔레그램 봇 토큰은 만료되지 않으므로 재로그인 절차가 없습니다.
- `getUpdates`는 읽은 위치(offset)를 `state/telegram_state.json`에 저장해 같은 답장을 두 번 읽지 않습니다.
  텔레그램은 미수신 업데이트를 24시간만 보관하므로 워크플로가 하루 이상 멈추면 그 사이 답장은 유실될 수 있습니다.

## 문제 해결

- **텔레그램이 안 와요**: Actions 탭에서 실패한 실행의 로그를 보세요. `chat not found`면 봇에게 먼저 메시지를 보냈는지 확인하고 `setup.py` 재실행.
- **체크인이 인식되지 않아요**: 항목 앞에 `운동`, `업무`, `언어`(또는 `공부`) 단어가 있어야 합니다. 값은 `O/X`, `했어/안 했어`, `✅/❌` 등을 인식합니다.
- **GitHub Actions가 60일간 활동이 없으면 예약 실행을 멈춥니다**: 저장소에 아무 커밋이나 하면 다시 켜집니다
  (매일 페이지를 커밋하므로 보통은 해당 없음).
